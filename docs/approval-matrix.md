# 承認マトリクス（提案・MECE）

目的: 「不可逆・外部影響・秘密」だけを承認対象にし、通常作業は止めない。
第一原理（オッカム）に基づく最小の承認集合。

## 区分

### A. 確認不要（既定で自律実行）
- 読み取り・ローカル検索・ログ確認
- テスト・lint・build・format の実行
- リポジトリ内ファイルの編集（秘密を含まない）
- 挙動不変リファクタ（テスト通過が条件）
- 非破壊の commit / push（追跡ブランチ）
- 文書ドラフト・Issue作成（リポジトリのルール内）
- **能力を減らす変更**（MCP/スキルの `disabled: true`、権限縮小）

### B. 1回確認（理由を示して承認を得る）
- 新規依存の追加
- 新規MCPサーバ・スキル・プラグインの追加/有効化
- 外部への公開・送信・課金
- データ削除
- force push / 履歴改変 / タグ付替え
- グローバル設定の変更（sudoers・systemd system unit等）
- 秘密情報の取り扱い

### C. 明示承認必須（例外なし）
- 監査・セキュリティ制御の無効化
- 秘密情報の外部送信
- ホストrootの破壊操作

## 適用範囲と優先順位
1. ユーザーの現ターン指示
2. プロジェクト固有 `AGENTS.md`
3. 共通コア（本マトリクス）
4. スキル（手順）

スキルはコアの安全制約を上書きできない。

## 完了定義
- 変更 + 決定論的検証（テスト/lint/build等）+ 残リスクの明示
- 無限ループ禁止（自動修正の再試行は2回まで）
- 曖昧点は「不可逆・仕様分岐・外部影響」のみ1回確認。それ以外は**仮定を明記して続行**

## 保留中の提案（権限拡大・未承認）
- 個人リポジトリでの自己承認・自動マージ（`review_flow.patch`）
- 不明点を質問せず仮定で続行する既定（`workspace.patch`）
→ 適用にはユーザーの明示承認が必要。
