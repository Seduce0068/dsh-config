  - `/dev/nvme0n1p1,p4,p5`, `/dev/sda1`, `/dev/sdb2` は **NTFS**
  - `/dev/nvme0n1p2` vfat（EFI）
- 外付け `sdb2` は 447G・空き445G（既存 `vm_backup` 2.2G）。

## 制約

- Timeshift の rsync モードは **Linuxファイルシステム（ext4等）** の保存先を前提とし、
  NTFSでは所有者・パーミッション・シンボリックリンクを保持できない（スナップショット用途に不適）。
- ルートと同一パーティションは保存先にできない（同一ディスクの故障に無防備）。

## 選択肢

| 案 | 内容 | 影響 |
|---|---|---|
| A | 外付けHDD/SSDに ext4 パーティションを作る（既存NTFSデータは退避・再作成） | **破壊的**。要バックアップと承認 |
| B | 内蔵に ext4 領域を追加（パーティション縮小が必要） | **破壊的**。危険度高い |
| C | Timeshiftを使わず、現行の**設定＋会話履歴＋Pocket ID DBのバックアップ**と、OS再インストール手順で復旧 | 非破壊。システム全体のロールバックは不可 |
| D | ext4イメージファイルをループバックで使用 | 非公式・壊れやすい。**非推奨** |

## 推奨

現時点では **C**（現行バックアップを継続）を維持し、システム全体のスナップショットが必要なら
A を計画的に実施する（事前に sdb2 の既存データを退避し、ユーザーの明示承認を得る）。
